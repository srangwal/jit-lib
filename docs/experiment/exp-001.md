The first pair on which we would test our hypothesis is mdBook (application) + elasticlunr-rs (library), both written in Rust.

- mdBook turns Markdown files into an online book or documentation website.
- elasticlunr-rs builds the book’s search index—the data that lets readers search its contents.

When mdBook builds a book with search enabled, it uses elasticlunr-rs to create that index. Our proposed experiment was to make this work faster, reducing the total book-building time while producing the same output.

This pair was interesting because mdBook uses the library in a predictable way:

- Every indexed entry has the same three fields: title, body, and breadcrumbs (its location in the book).
- Entries receive consecutive identifiers: 0, 1, 2, …
- mdBook builds a fresh index, adds entries, and saves it.

The library supports more general arrangements. An agent might use mdBook’s guarantees to simplify its internal data structures and reduce unnecessary work.

The pair was selected, but the improvement was still a hypothesis. The records report preparation and baseline testing; no specialized implementation or demonstrated speedup existed. sfz / Tera was retained as the backup.
